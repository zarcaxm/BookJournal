# BookJournal

BookJournal is a browser-based writing journal built with React, TypeScript, and Vite. It lets you create books, write and publish dated entries, view a compiled manuscript, and export that manuscript as a PDF. It is also configured as an installable Progressive Web App (PWA).

## Requirements

- [Node.js](https://nodejs.org/) `20.19+` within the Node 20 release line, or `22.12+`
- npm (included with Node.js)
- A modern web browser

The Node.js requirement comes from Vite 8. No server, database, API keys, or environment variables are required.

## Setup and run

From the project directory, install the locked dependencies:

```bash
npm ci
```

Start the development server:

```bash
npm run dev
```

Open the URL shown in the terminal (normally `http://localhost:5173`). Vite enables hot module replacement, so saved source changes appear in the browser automatically.

If you intentionally change dependencies, use `npm install` instead and commit the resulting changes to both `package.json` and `package-lock.json`.

## Available commands

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the local Vite development server |
| `npm run build` | Type-check the project and create a production build in `dist/` |
| `npm run preview` | Serve the contents of `dist/` locally for a production-build check |
| `npm run lint` | Run Oxlint over the source code |

To check the production build locally:

```bash
npm run build
npm run preview
```

Then open the URL printed by Vite (normally `http://localhost:4173`). `vite preview` is intended for local verification, not as a production web server.

## Data and offline behavior

Book and entry data is stored only in the browser's `localStorage`, under the key `bookjournal.v1`. It is not synced to a server and is specific to the browser profile and site origin. Clearing site data will remove the journal data for that origin, so export important manuscripts as PDFs before clearing browser storage.

The PWA service worker caches the built application for offline use and checks for updates automatically. PWA installation and service workers require HTTPS in production; `localhost` is treated as a secure context during development. The UI uses Google Fonts, so the first load is best done with an internet connection; fetched font resources are cached by the service worker.

## Deployment

Deploy the generated `dist/` directory to any static host. The current PWA configuration assumes the app is hosted at the domain root (`/`). Configure the host to:

- serve the site over HTTPS;
- return `index.html` for application navigation requests; and
- avoid renaming or omitting generated PWA files such as the manifest and service worker.

## Regenerating app icons

The checked-in PWA and Apple touch icons are generated by `scripts/generate-icons.mjs`. After changing the icon source in that script, regenerate them with:

```bash
node scripts/generate-icons.mjs
```

This command uses the installed `sharp` development dependency and writes the generated images to `public/`.
