# BookJournal

BookJournal is a browser-based writing journal built with React, TypeScript, and Vite. It lets you create books, write and publish dated entries, view a compiled manuscript, and export that manuscript as a PDF. It is also configured as an installable Progressive Web App (PWA).

## Requirements

- [Node.js](https://nodejs.org/) `20.19+` within the Node 20 release line, or `22.12+`
- npm (included with Node.js)
- A modern web browser

The Node.js requirement comes from Vite 8. No server, database, API keys, or environment variables are required.

## Setup and run

From the project directory, install the locked dependencies:

```bash
npm ci
```

Start the development server:

```bash
npm run dev
```

Open the URL shown in the terminal (normally `http://localhost:5173`). Vite enables hot module replacement, so saved source changes appear in the browser automatically.

If you intentionally change dependencies, use `npm install` instead and commit the resulting changes to both `package.json` and `package-lock.json`.

## Available commands

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the local Vite development server |
| `npm run build` | Type-check the project and create a production build in `dist/` |
| `npm run preview` | Serve the contents of `dist/` locally for a production-build check |
| `npm run lint` | Run Oxlint over the source code |
| `npm test` | Run the Vitest unit and integration suite |

To check the production build locally:

```bash
npm run build
npm run preview
```

Then open the URL printed by Vite (normally `http://localhost:4173`). `vite preview` is intended for local verification, not as a production web server.

## Data, privacy, and offline behavior

By default, book and entry data lives in the browser's `localStorage` under the key `bookjournal.v1`. From the library you can also choose a folder (Chrome or Edge) and keep the journal as `bookjournal.json` there — a Google Drive sync folder works well. The chosen folder handle is remembered in IndexedDB; if permission is lost, reconnect from the library. Browser storage remains a mirror and fallback.

Nothing is uploaded to a BookJournal server. There is no account system, analytics, or third-party tracking. Notion import and PDF export run entirely in the browser. Journal text is stored in plaintext on the device (and in any folder or cloud sync you choose), so treat shared computers and site-data clears accordingly — keep a folder backup or export manuscripts as PDFs before clearing site data. Do not commit `bookjournal.json` if you point folder storage at a git checkout; it is gitignored for that reason.

Fonts ship with the app (self-hosted via Fontsource), so the UI does not call Google Fonts or other font CDNs. The PWA service worker caches the built application — including those font files — for offline use and checks for updates automatically. PWA installation and service workers require HTTPS in production; `localhost` is treated as a secure context during development.

## Deployment

Pushing to `main` (or publishing a GitHub Release, or running the workflow manually) builds and deploys `dist/` to **GitHub Pages** via [`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml). The workflow runs `npm ci`, `npm test`, and `npm run build`, then publishes with `actions/upload-pages-artifact` and `actions/deploy-pages`.

Live site:

`https://zarcaxm.github.io/BookJournal/`

CI sets `BASE_PATH` from `actions/configure-pages` so Vite and the PWA manifest target `/BookJournal/`. Local builds keep `base: '/'`. For a root-domain install via a custom domain, set `BASE_PATH=/` on the workflow build step if assets should resolve at `/`.

### Manual / other hosts

You can still deploy `dist/` to any static host. Configure the host to:

- serve the site over HTTPS;
- return `index.html` for application navigation requests; and
- avoid renaming or omitting generated PWA files such as the manifest and service worker.

## Regenerating app icons

The checked-in PWA and Apple touch icons are generated by `scripts/generate-icons.mjs`. After changing the icon source in that script, regenerate them with:

```bash
node scripts/generate-icons.mjs
```

This command uses the installed `sharp` development dependency and writes the generated images to `public/`.
